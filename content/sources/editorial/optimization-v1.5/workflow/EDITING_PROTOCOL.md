# 簡式對話潤飾流程

1. **定位原稿。** 讀使用者指定範圍與必要前後文，確認真正可維護來源及格式。缺稿就說明，不從摘要重建。
2. **理解原句。** 依 characters/CHARACTER_NAMES.md 辨識角色，確認說話者、對象、目的、已知資訊、情緒與關係。先看是否真的需要修改。
3. **局部潤飾與自然化。** 對照 `../rules/NATURAL_DIALOGUE.md`，消除不必要的條例、列舉與簡報式談判；保留各項實義和人物的資訊狀態。 用角色風格調整措辭與節奏，保留原意及資訊。必要時只換幾個字，不追求全篇煥然一新。
4. **回讀。** 對照事實、情緒、意圖與前後承接，檢查未新增條件、承諾、證據、陰謀、能力或親密程度。
5. **格式檢查。** 保留 Scene／CG／選項／角色等 ID 與標記、邏輯、數值；原稿嵌在資料內時使用相關解析或既有檢查。選項文字、旁白與動作預設不修改。
6. **交付。** 直接修改指定來源，或依使用者要求提供平行稿。簡短附上幾組代表性前後差異；未做遊戲運行驗證就不宣稱實裝驗證完成。

## 尺度示範（虛構台詞，非既有正文）

原意：指出期限不切實際。

- 普通原句：「這個期限不合理，我們沒有足夠時間完成。」
- 莎莉雅式潤飾：「期限倒是訂得漂亮。可惜一天還是只有那麼長。」

僅在前文已明確交代工作與期限時，這樣縮寫才不會丟失資訊。若原句還承擔正式拒絕或明示無法完成的功能，應保留「這個期限辦不到」等明確表態。

原意：請對方先休息，自己接手眼前工作。

- 普通原句：「你先休息，這裡交給我。」
- 卡利斯式潤飾：「先歇一會兒。這裡有我，你不用一直撐著。」

不能把這句改成「所有敵人我都會解決」，那新增了承諾與事件內容。

不要用任何樣例當批次替換模板。比起增加新花樣，先保持原句在當場的作用。

完成前抽讀實際對話的承接，不能只靠搜尋編號判斷已去除 AI 味。人物風格與自然交談兩項都必須檢查。依照 `../rules/SHORT_DRAMA_REFERENCE.md` 回讀對話是否真的接住前一句、是否多做了一次解說，以及收尾是否符合當場目的。

回讀時確認「嗯」是聽見還是答應，「吧」是提議還是推測，「那」和「所以」是否真的承接已知前提。軍令與談判的承諾力度依原稿。
