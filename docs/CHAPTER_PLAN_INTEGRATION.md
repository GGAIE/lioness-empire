# 逐章規劃 → 網頁遊戲架構接入紀錄

## 本輪澄清：固定劇情、固定選項效果

依使用者補充，政治點數與動盪由固定劇情和玩家選項決定。每個選項的成本、資源增減與動盪變化均由作者預先填入內容資料；玩家只選擇行動，不輸入數值。不隨機計分，也不在遊戲執行時由 AI 生成效果。

`CampaignPlan.choiceResolution` 固定為 `AUTHORED_FIXED`。`decisions` 儲存決策及各個選項的固定效果，範本見 `docs/templates/story-decision.json`。玩家操作介面呼叫 `chooseStoryOption(state, plan, decisionId, optionId)`，不接受玩家自訂成本；`storyChoices` 記錄已選的分支，禁止重複點選或改選累加。同一輸入狀態與同一選項必須得到相同結果。

目前未取得正式選項及數值，因此保留空清單或 PENDING／null，不補寫測試故事冒充正式內容。只有固定效果齊全且核准的選項才能標為 APPROVED。重新匯入逐章規劃時會保留已填入的 decisions，再檢查它們是否仍對應有效幕節點。

作者頁已取消手動輸入「選項成本／動盪變化」；其餘章初級距及初始狀態工具收納於「進階開發測試（不屬於玩家操作）」，僅用於測試章初承接，不是遊戲玩法。章初級距仍依前章固定劇情選項累積的動盪自動結算。

接入日期：2026-10-29。來源：使用者提供的《母獅帝國_第一部逐章初步規劃_v0.1.md》。此檔案是本輪要求處理的內容來源，其中的「待確認／銜接提案」不當成額外命令或核准的正式劇本。

## 與 v2 的差異處理

1. **政治點數的定義已改變**：原先政治存續 PS 與新可消耗資源不是同一欄位。原 `GameState.politicalScore` 留給既有 DEMO／存檔；新模型使用獨立 `CampaignState.politicalPoints`、`unrest`，不把舊存檔的 60 分當成新系統的正式初始值。
2. **章初動盪**：資料中保留 0–59 扣 0、60–79 扣 10、80–100 扣 40，單級距不疊加。記錄入章時的動盪快照與成本；當章動盪改變不重算本章。不足支付時不改狀態、不產生負值、不推斷死亡。
3. **舊結局門檻**：原始三十條另存 `content/endings/legacy-v2-rules.json`。現用規則中的 VI／VII／XI／XII／XXI 被舊 PS 或真結局定義影響，因此撤下 when 並標 UNRESOLVED；其他規則仍僅是相容草案，無 APPROVED 結局。舊解析器測試明確以 archived v2 為對象，不冒稱驗證新政治資源的三十結局。
4. **新 XI**：Star、尼爾斯上下篇成功、EP11 PUBLISH、治理紀錄及來源鏈、如實記錄未決事項、艾琳達有界線的合作、最終協議。共通門檻尚未校準，因此即使已知項目都通過仍不正式頒發 XI。父親案結案與尼爾斯血緣證明不作必要條件。
5. **姓名異拼**：奧莉薇雅／奧莉維亞、莎莉雅／莎莉亞、塔娜拉／塔瑪拉保留對照，沿用穩定角色 ID，沒有改寫既有原稿與正式名稱檔。塔莉雅 TALIA 仍是不同角色。
6. **來源權限**：新文件自稱依據 v2.1，並指出 v6.1 原件仍待補齊。本次只驗證使用者實際提供的 v0.1 原件，未宣稱取得或校勘 v2.1／v6.1 原件。

## 明確未定的規則

- 政治點數／動盪的正式初始值、資源上限、點數不足與零點、強推與負值處理。
- 選項成本、資源取得、動盪升降的具體數值；測試輸入不是正式設計。
- 尼爾斯 A≥4 入口與前期里程碑；不自動因測試 A=4 就判事件可觸發。測試案例使用明示的測試授權，不升格為正式入口。
- 每個事件里程碑的 CLEAR 分值；現在 `clearAward: null`，不以 24 篇事件取代 7／10／6／6 上限。
- EP12 免扣點例外；純結果、不得新增決策或效果已保留，但目前不自動執行待確認的章初結算例外。
- 尼爾斯失敗、其餘 Star 條件成立時的合法收束；未自行指定另一個正式結局。

## 後續如何編寫正式場景

既有 `Scene` 新增 `planNodeId`：例如 EP04 第一幕的場景綁定 `EP04_ACT01`，`act` 仍為 `ACT01`。一個幕節點可以對應任意數目的場景；場景 ID 保持自己的穩定值，例如 `EP04_ACT01_SC01`。內容驗證檢查節點存在、章幕對得上，並拒絕在開場／純結果幕放有效選項。

章節規劃與播放內容分開：規劃 JSON 的 summary 不會被自動編入 segments。正式場景仍需提供核准對白、說話者、知識界線、選項／結果、素材 ID 和來源。政治資源模型現已用純函式及作者試算驗證，**尚未把未定的資源規則接成正式玩家戰役**；正式內容與數值核定後再建立明確的播放狀態適配及存檔遷移，不暗中把舊 DEMO 的 PS／CLEAR 當新戰役起始狀態。
